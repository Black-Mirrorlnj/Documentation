== Introdução

Este documento descreve os requisitos funcionais e não funcionais para o sistema ScoreSync, 
um software projetado para capturar, sincronizar e exibir estatísticas de 
jogadores em servidores de Garry’s Mod. O objetivo é fornecer aos administradores e 
jogadores uma plataforma centralizada para consulta de desempenho.



O ScoreSync surge da necessidade de oferecer maior transparência e competitividade dentro dos servidores, permitindo que dados de desempenho sejam armazenados de forma persistente e segura. Atualmente, muitos servidores dependem apenas de sistemas locais e temporários de pontuação, o que limita a análise histórica e comparativa entre partidas

Além disso, o sistema busca padronizar a coleta de métricas relevantes, garantindo consistência nas informações registradas independentemente do modo de jogo utilizado. Dessa forma, torna-se possível implementar rankings globais, estatísticas detalhadas e indicadores de desempenho que incentivem o engajamento da comunidade.

Outro aspecto importante do projeto é a escalabilidade. O ScoreSync foi concebido para suportar múltiplos servidores simultaneamente, permitindo que diferentes comunidades utilizem a mesma infraestrutura centralizada sem comprometer desempenho ou integridade dos dados.

Por fim, o sistema também prioriza segurança e confiabilidade na transmissão das informações, utilizando protocolos seguros de comunicação e validação de dados. Isso garante que as estatísticas armazenadas reflitam fielmente os eventos ocorridos no jogo, evitando inconsistências, manipulações indevidas ou perda de informações críticas.

== Visão Geral do Projeto

Script de Servidor (Addon): Desenvolvido em GLua para monitorar eventos internos 
(kills, mortes, tempo de jogo).

Backend/API: Uma aplicação que recebe os dados do servidor e os armazena 
em um banco de dados para consulta via Web ou Dashboard.

Banco de Dados: MYSQL/O Banco de Dados do próprio VSCODE

== Identificações dos requisitos:

RF001[SystemRT]:O sistema deve capturar eventos de pontuação (Kills/Deaths) em tempo real.

RF002[Sincronização P/SQL]:O sistema deve sincronizar o progresso do jogador com um banco de dados externo via 
HTTP/HTTPS.

RF003[System Score]:O sistema deve permitir que o jogador consulte seu próprio score via comando no chat 
(ex: !score).

RF004[Placar de Pontos]:O sistema deve possuir uma interface Web para visualização de um Ranking Global 
(Leaderboard).

RF005[Servers]:"O sistema deve suportar múltiplos servidores simultâneos, 
diferenciando a pontuação por ID de servidor."

RF006[Admin]:Administradores devem ser capazes de resetar ou editar scores através 
de um painel de controle.

RF007[Relatório de Observações]: Em tempos regulares, o cliente receberá 
através do devs um relatório, onde será feitas perguntas acerca do app. Assim termos um feedback
de como nosso sistema está funcionando perfeitamente ou não.

RF008[Inscrição in-game]: Deve-se obrigatoriamente estar logado e pareado com o Garry’s Mod
junto com o software para ocorrer o emparelhamento. Já logado, o software exibirá o id
da partida e os outros jogadores.

== Descrição geral do sistema:

O sistema funcionará como um ecossistema onde o servidor de Garry's Mod 
atua como o emissor de dados. Sempre que um evento relevante ocorrer 
(ex: o fim de uma rodada no modo MM ou TDM), o addon enviará um payload 
JSON para o servidor web.

Evento no Jogo: Jogador elimina outro.

Hook (Gancho): O script GLua intercepta o evento PlayerDeath.

Processamento: O script verifica os SteamIDs envolvidos.

Sincronização: Uma requisição http.Post é enviada à API.

Armazenamento: A API valida a chave e salva os dados no banco (MySQL/PostgreSQL).


== Descrição dos usuários:

Jogadores: Buscam competitividade e visualização de progresso. 
Interagem via comandos de chat ou site.

Administradores de Servidor: Interessados em gerenciar a comunidade e 
moderar possíveis abusos de pontuação.

Desenvolvedores: Interessados em expandir o sistema ou integrar com outros modos de jogo.
